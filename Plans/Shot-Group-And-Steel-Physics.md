# Shot group and steel physics

Goal: Complete ladder outcome 3. From the current editable Mac solver inputs, the owner chooses a shot count and seed, runs a fresh simulated group, sees every impact against a round steel plate, and inspects the spread and hit statistics. A separate center/edge demonstration shows the plate's physical reaction and settling. The calculations and target motion are Swift implementations, not lookups from saved results. Validate both against separate, fixed web-engine cases and independent behavior checks. This is one focused plan for outcome 3, with two commit checkpoints.

## Starting state and decisions

- Repository root: `~/Developer/First Round/`. The Xcode app and test target already build on Mac. The app has ten editable cartridge starting loads and a working trajectory table. `TrajectorySolver` supports calm-air zero followed by constant or seeded Moderate wind. `SeededRandom` implements the legacy MT19937/uniform sequence; a normal sampler is not yet present. The existing golden and wind fixtures stay unchanged and test-only.
- The older web engine's `GameBuild/engine/src/match/simulator.cpp` supplies the per-shot model: one calm zero at target range, then new muzzle velocity, BC, release-angle, cant, and 3D wind-variation draws per shot. Its `GameBuild/app/src/engine-bridge/match-sim.ts` returns scatter about the deterministic impact center. The mean wind and the player's correction belong to the deterministic solve, not to this scatter source. Use source revision `a96c8f67ed2f395d111b1da5613f151823f7742c` for captured references. The older `GameBuild/engine/src/rendering/steel_target.cpp` and `GameBuild/app/src/engine-bridge/steel-target.ts` are the steel reaction references. Read them during implementation; no Swift source, test, app resource, or Xcode build step may need the old checkout.
- Coordinates stay `+x` right, `+y` up, `-z` downrange. An uncorrected group is centered on the current computed shot-mode displacement at its selected range. An “Apply computed correction” toggle places that deterministic center on the plate center; the random scatter is then added. The toggle is a numerical demonstration, not a player aiming or dial mechanic. A fixed seeded gust field contributes to the deterministic center at the selected field clock; the per-shot wind SD fields add independent variation. Do not add the mean wind twice.
- The web `Match::getMeanRadius()` actually returns **RMS distance from the aim origin**; `getGroupSize()` returns a **bounding-box diagonal**, not the farthest distance between two shots. Preserve those values only when comparing legacy output and label them by their real definitions. The Mac screen reports actual mean radius about the calculated group center and actual extreme spread (greatest pairwise separation). Do not silently use the web names for different statistics.
- Verify this milestone on **macOS only**. No iPhone UI work, simulator runs, or iOS test gate. Keep existing box fields, unit selectors, and trajectory table working.

### 1. Seeded shot groups and visible spread — complete · 2026-09-25

First capture one fixed 50-shot old-engine group from the 6.5 Creedmoor 140 gr reference load, ISA sea level, 300 yd (`274.32 m`), seed `12345`, and the web match dispersion (`MV SD 2.7 m/s`, BC SD fraction `0.005`, rifle cone diameter `0.5 MOA`, cant and wind SDs zero). Also capture a bulk configuration from the same load (`MV SD 5.2 m/s`, BC SD `0.015`, rifle cone `1.5 MOA`) and a smaller nonzero-wind-variance case. Store input units, exact ordered per-shot impact offsets and sampled MV/BC values, aggregate legacy metrics, generator command, source revision, and SHA-256 in the new fixture/manifest. The generator may accept the old checkout as an explicit argument for offline regeneration; app and tests must not call it. Do not replace the existing fixed vectors.

Implement the random normal sequence and dispersion engine. The legacy draw order is: clipped normal MV; clipped normal BC (fraction of nominal); uniform release angle and area-uniform accuracy-cone radius; uniform cant; clipped normal crosswind, headwind, and updraft. Each normal draw is clipped to ±3 SD. The accuracy input is the **diameter** of the angular cone, so radial sampling uses `(diameter/2) × sqrt(U)`. Reuse the same cached target-range calm zero for all shots, scale the zeroed velocity by sampled MV without resampling spin, apply release angle/cant, simulate the varied BC and wind, and interpolate impact at the selected range. Match the old `1 ms` flight step and zero-at-target search (`1000` maximum iterations, `1e-6 m` requested tolerance, `30 s` max time) for reference cases. Refactor the existing solver so this reuse does not change the 36-case matrix or current Mac table.

The group screen accepts a shot count from **1 to 500**, a visible UInt32 seed, target range, round plate diameter, and editable MV SD, BC SD (% of nominal), rifle accuracy (MOA cone diameter), cant limit (degrees), crosswind SD, headwind SD, and updraft SD. Defaults come from the catalog's nominal cartridge precision and grade values; use the old 6.5 match numbers above for the matching default, and annotate any values without a direct match as starting assumptions. Wind SD defaults to zero, matching the early web catalog. Every value remains independently editable. Compute from current box/atmosphere/wind inputs; reusing a saved trajectory row is allowed only as a cached result for the **same current inputs**, never as a fixture answer. Editing an input clears the old group until Run is pressed again. Run the bounded volley off the UI thread, show progress and Cancel, and publish only a complete group or an explicit cancellation/error.

Plot every impact in a fixed-scale target-plane chart with a labeled plate outline and bullet-size-aware hit color; allow selecting a point to see its x/y offset and sampled MV/BC. Show the seed, count, hit count/rate, group-center offset from plate center, **mean radius about group center** (`sum(distance(shot, groupCenter))/N`), **extreme spread** (maximum pairwise shot distance), and **RMS radius from intended center** (`sqrt(sum(x²+y²)/N)`) with that last label explicit. For one shot, extreme spread is zero; for zero shots, the Run control rejects the request. Hit test uses plate radius plus bullet radius. Show uncorrected and “Apply computed correction” modes so the owner can see a shifted group versus a centered one.

### 2. Steel hit and reaction preview — ready for owner review · 2026-09-25

Port the **round hanging plate** path needed for the next playable shot loop: circular intersection in the target plane with bullet-radius line break; a plate hit applies projectile momentum at its impact point; plate mass from steel density/area/thickness with the legacy minimum mass; rotational inertia; two top chain constraints; gravity, damping, twist spring/limit, and settle detection. Preserve the old coordinate and quaternion convention and the `1 ms` maximum internal physics substep. Use the old `steel_target.cpp` constants and chain geometry as written; keep them in named Swift constants. Centered impact should swing downrange, a right/left rim impact should add opposite signed twist, and the plate should settle facing the shooter. The intended first plate is a 6-inch (`0.1524 m`) round plate, `0.0127 m` thick, with a 140 gr 6.5 mm bullet; include small 2-inch and large 12-inch edge cases. Record hit location, incoming velocity, plate pose, and settle state. Defer impact paint/texture, rectangular silhouettes, target-specific hinges/latches, audio, and 3D rendering to later outcomes.

Capture deterministic old-engine cases for center and ±rim strikes on the 6-inch plate, plus a hard off-center strike on 2-inch and 12-inch plates. Record center of mass, normal/quaternion, angular velocity, and moving state at defined elapsed times (`0`, `0.02`, `0.2`, `1.0 s`) and when settled (or at a documented fixed cap). Use the same rig dimensions as the old bridge, and put all inputs, timing, generator command, revision, and SHA-256 in `Reference/README.md`. Tests must distinguish a true miss (no impulse) from a line-breaking graze (hit and reaction). Use unit tests for invariants and pose comparisons; initial target is `≤0.001 m` for positions and `≤0.02 rad` for orientation/twist, with any failure investigated rather than widening limits silently.

Add a Mac steel preview beside or below the shot plot. Selecting a plotted hit can replay its strike; buttons for a reproducible center hit and left/right edge hits make the difference observable even if the sampled group misses. Show a front view plus swing/twist-versus-time readouts or a simple animation driven by computed poses, with a Replay control and a visible “settled” state. It must use the Swift physics result. No RealityKit range or player trigger is needed here.

**Check:** The Mac test suite and app build pass, including unchanged solver/vector/wind tests. The five steel reference cases match the pinned engine within the position/orientation/angular-velocity tolerances. Invariant tests confirm a miss receives no impulse, a bullet-radius graze reacts, center strikes swing downrange, left/right rim strikes twist with opposite signs, and 2-, 6-, and 12-inch plates settle facing forward. The front-view chains use the old web bridge's outward-splayed display endpoints to avoid crossing visually; the underlying legacy physics anchors are unchanged for parity.
